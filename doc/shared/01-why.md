# 为什么用 BoomNetwork

## 它是什么

BoomNetwork 是一个**自权威帧同步网络库**，让多个玩家通过网络实时同步游戏状态。核心哲学：每个玩家是自己角色的权威，操作零延迟，不做预测回滚，冲突交给仲裁者（详见 [core-philosophy.md](04-core-philosophy.md)）。客户端用 C#（适配 Unity），服务器用 Go。

## 它解决什么问题

多人实时游戏需要解决三个核心问题：

```
1. 所有玩家看到相同的画面（一致性）
2. 操作立刻有反馈（低延迟）
3. 断网后能恢复（可靠性）
```

帧同步的做法：服务器不计算游戏逻辑，只负责**收集所有玩家的输入，按固定帧率广播**。每个客户端收到相同的输入，独立执行相同的逻辑，得到相同的结果。

```
传统状态同步:  客户端 → 操作 → 服务器计算 → 结果广播 → 客户端渲染
帧同步:       客户端 → 输入 → 服务器转发 → 所有客户端各自计算 → 各自渲染
```

## 什么时候该用它

| 场景 | 推荐 | 说明 |
|------|------|------|
| 派对/跑酷/竞技 | ✅ | 输入简单，逻辑确定性好 |
| 格斗/动作 | ✅ | 对延迟敏感，帧同步延迟最低 |
| MOBA (10人以内) | ✅ | 帧同步经典场景 |
| MMO (大量玩家) | ❌ | 帧同步不适合几百人同屏 |
| 回合制 | ❌ | 不需要实时同步 |

## 和自己撸网络代码相比

| | 自己写 | BoomNetwork |
|---|--------|-------------|
| TCP/KCP 切换 | 改半天 | 换一行代码 |
| 粘包拆包 | 容易写错 | 内置，经过单元测试 |
| 心跳断线检测 | 到处 if/else | ConnectionManager 自动管 |
| 断线重连 | 和业务逻辑耦合 | 策略模式，可插拔 |
| 热路径内存分配 | 不知道哪里在 new | ArrayPool + RingBuffer，压测验证零分配 |
| 压过测吗 | 没有 | 3000 人 TCP / 1000 人 KCP 已验证 |
