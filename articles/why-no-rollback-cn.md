# 为什么我们的多人游戏框架不做回滚 — BoomNetwork 的自权威模型

> 适合发布到：掘金 / 知乎 / SegmentFault

---

多人游戏的网络同步，圈内默认答案是"预测+回滚"。Photon Fusion 做了，Netcode for GameObjects 做了，GGPO 把它做成了格斗游戏的事实标准。

**BoomNetwork 反过来 — 核心层不做回滚。**

不是因为做不到（我们实现过，然后删掉了），而是想清楚了：对 80% 的多人游戏来说，回滚带来的复杂度远大于它解决的问题。

## 回滚到底在解决什么

先理解因果链：

```
你按移动 → 客户端预测执行 → 等服务器确认 → 服务器说"不对" → 回滚到确认状态 → 重新模拟
```

**回滚解决的是"预测错误"。** 关键在于：预测错误的前提是"我不是权威"。如果我就是权威呢？

## 自权威模型：如果我就是权威

```
传统模型：
  我按移动 → 猜测服务器会怎么算 → 可能猜错 → 需要回滚

BoomNetwork 模型：
  我按移动 → 我就是移动了 → 广播给其他人
  其他人收到 → 直接信任 → 插值平滑
```

三条公理：
1. **自己的操作零延迟** — 按下就生效，不等任何人
2. **别人的状态直接信任** — 不质疑、不预测，只做视觉平滑
3. **冲突由仲裁者定** — 谁命中谁，一锤定音，不回滚

## 代价是什么

| 维度 | 回滚模型 | 自权威模型 |
|------|---------|-----------|
| 接入复杂度 | 需要理解预测/回滚/快照/因果链 | SendInput + OnFrame，30 行代码 |
| 代码量 | +30-40% 同步代码 | 核心逻辑不变 |
| 调试难度 | Bug 来源 ×4 | Bug 来源不变 |
| 仲裁延迟 | 无（本地立即确认） | 1 RTT（命中判定需等仲裁者） |
| 极端竞技 | 逐帧公平 | 做不到格斗级公平 |

我们接受了仲裁延迟（用视觉预测缓解），放弃了格斗级公平（非目标场景）。换来的是：接入复杂度降一个数量级。

## 在 AI 时代这意味着什么

2026 年，越来越多人用 AI 写游戏代码。

让 Claude/GPT 正确实现预测+回滚？大概率写出来的代码有隐蔽的 desync bug。

让 AI 正确实现 SendInput + OnFrame？几乎不会出错。

**概念越简单，AI 生成的代码越可靠。** 这不是偶然 — 这是第一性原理和 AI 时代的共振。

## 实际数据

- 4,000 玩家并发，15 分钟零断连
- 每玩家 0.68 KB/s 上行，3.14 KB/s 下行
- 服务器 200 MB 内存，20 fps 稳定
- 空闲时零带宽消耗（Silent When Idle）
- Go 服务器热路径零 GC 分配

## 覆盖范围

✓ 动作/跑酷/赛车 — 自权威零延迟，体验完美
✓ MOBA/休闲射击 — 射击者权威 + 视觉预测
✓ 派对/合作/沙盒 — 冲突少，仲裁延迟不敏感
✓ 建造/经营 — 各干各的，几乎不需要仲裁

△ 格斗（逐帧判定）— 需要 GGPO，可通过中间件扩展
△ 硬核 FPS — 需要精确延迟补偿
